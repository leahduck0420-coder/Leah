# 联合搜索与预算

预先按当前区域和作用位置构造有限池，并保存每条历史的合法后继。选择器只能查询已付费的候选。有相同执行键的历史共用执行证据，搜索沿实际到达的历史扩展。控制路径、评分及访问顺序在 search_trace.jsonl 中可追踪。

Search-0 选择无策略根计划。Search-1 在本池单动作中选最快；另外按功能输入契约复测 Stage A 单策略，得到实验 B2。Search-2 采用固定非降规则顺序及确定性参数顺序。Greedy 每层保留一个已测前缀。Beam 先保留不同位置组合，再按真实延迟填满宽度。静态优先级使用 tile、merge、切片和可选 DAG 深度/边数，作为预算分配顺序。选择结果以通过门禁的真实延迟判定。

每个预算包含基线；前期为后续层保留查询份额。候选耗尽或全部被拒绝可提前结束。Greedy 和 Beam 比较同一 depth、budget 和区域。预算是上限，实际使用量也必须一起报告。系统共享已测样本以减少 GPU 重复工作，每种算法对自己首次访问的每个候选独立扣费，缓存命中不减少计费。search_time 是实际控制路径墙钟，controller_seconds 单列排除测量回调；charged_evaluation_seconds 对每个查询计入原进程时间；standalone_total_seconds 加入公共池构建和自身控制时间。编译候选数、warmup 调用次数和不同特化数分别记录。

策略完成选择后才填完剩余有限池并计算 measured oracle。regret=(selected−oracle)/oracle。失败计划没有 oracle 延迟。报告同时给出池总数和合格测量覆盖数。消融控制顺序、参数、结构引导、宽度与深度、DAG 启发式。关掉结构预剪枝仍要通过最终合法性与数值门禁。
